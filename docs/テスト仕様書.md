# WAKIASEMEMO テスト仕様書

*作成日 2026-11-17　／　元にした資料: メモ帳アプリ 仕様書（2026-10-15）、テスト仕様書サンプル、リポジトリのコード*

すべての機能要件（F-01〜F-09）と非機能要件（N-01〜N-06）に、1件以上のテストケースを対応させています。

## テスト方針と環境

- **対象**: WAKIASEMEMO のブランチ T-GRD-05（コミット 4176b5d、2026-11-17 時点）。期待結果は、このコードを読んで書いた。
- **環境**: docs/setup.md の手順で docker compose up -d --build → docker compose exec app npx prisma migrate dev。データを空にした MySQL を使う（phpMyAdmin http://localhost:8080/ → memo → memos →「操作」→「テーブルを空にする（TRUNCATE）」。id は 1 から振り直される）。
- **API テスト**: Chrome で http://localhost:3000/api/memos を開いたタブ（以下「API 用タブ」。メモ画面は動かない）で F12 → コンソールを開き、次の api() を貼り付けて使う（初回は allow pasting と入力して貼り付けを許可する）。api() は、ステータスと本文をコンソールに出し、JSON を返す。X-Client-Id は "tester" を送る。curl や REST クライアントで同じリクエストを送ってもよい。

  ```js
  const api = async (method, path = "", body, clientId = "tester") => { const res = await fetch("/api/memos" + path, { method, headers: { "Content-Type": "application/json", "X-Client-Id": clientId }, body: body === undefined ? undefined : JSON.stringify(body) }); const text = await res.text(); console.log(res.status, text); try { return text ? JSON.parse(text) : null; } catch { return text; } };
  ```
- **画面テスト**: Chrome の最新版で http://localhost:3000/ を開き、手で操作する。F12 は開発者ツール、F5 は再読み込み。リアルタイム同期は、同じ PC の2つのブラウザ（端末A・端末B）を同時に開いて確認する。ステータスは、エディタ下の「削除」ボタンの左（「未保存」の印の右）に出る文字。
- **前提の記号**: 「メモ○件」は、未削除のメモがその件数あることを指す。「当日のYYYY-MM-DD」は、サーバーの日本時間（TZ=Asia/Tokyo）の日付。「&lt;id&gt;」は、その時に作ったメモの実際の id に置き換える。
- **記入方法**: 薄い黄色の欄（担当・実行日付・結果・実際の結果・備考）に記入する。結果はプルダウンの OK / NG / 一部未確認 から選ぶ。記入例: 担当「佐々木」、実行日付「2026-11-20」、結果「NG」、備考「500 ではなく 400 が返った」。OK 以外のときは、実際に起きたことを備考に必ず書く。

## 合格基準

- 上記のすべてのケース（追加項目を含む）が「期待結果」のとおりになる。ただし T-API-05・06・16 と T-ADD-09 は、現行実装の結果（500）を期待値とする。
- T-ADD-08 と T-ADD-21 は結果を記録できれば合格とし、その値を「要確認」の判断に使う。
- 重大な不具合（データの消失、他端末への誤った反映）が残っていない。
- 「一部未確認」が残る場合は、確認できなかった理由を備考に書き、合格とするかを担当者で決める。

## 既知の制約

- 入力制限の違反（タイトル101文字・本文10,001文字）、リクエストボディ 1MB 超過、壊れた JSON は、400 ではなく 500 で返る（仕様書どおり）。400 に改善する場合は T-API-05・06・16、T-ADD-09 の期待結果を更新する。
- 同時編集の競合解決はしない。あとから保存した方が残る（仕様書の対象外）。
- 下書きはブラウザごとに1つ。同じブラウザのタブ同士は下書きを共有するため、リアルタイム同期の確認は別々のブラウザで行う。
- ブラウザの離脱確認の文言と、通信エラーのときの文言（Failed to fetch など）は、ブラウザが決める。
- メモ画面は crypto.randomUUID を使うため、http では localhost でしか動かない（T-ADD-19）。
